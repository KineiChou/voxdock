# Console administrator account

The service keeps a single administrator in `console-account.json` in its private data directory. The file is mode 0600 and contains a scrypt password hash, username, account revision, credential revision, and remote-management preference. Account writes replace the file atomically. Only one service/recovery process may own this directory at a time.

On first startup, an existing configured password hash is imported with username `admin`. Otherwise the service generates a random password and saves it with username `admin` in mode-0600 `bootstrap-credentials.txt`. Credentials are never printed or returned by HTTP. Later starts reuse the saved account. Username/password rotation deletes the initial credential file and invalidates existing browser sessions. Changing only remote-management access preserves audit sessions.

`GET /admin/v1/account` returns `username`, `revision`, and `allow_remote_management`. `PUT` requires those fields, `current_password`, and optional `new_password`; successful output is `{ account, login_required }`. Updates require the current revision and current password. Browser updates additionally require the configured Origin, a valid session and CSRF token, and are limited to five attempts per minute. Usernames use 1–64 ASCII letters, digits, underscores, dots, or hyphens, starting with a letter/digit. Passwords use 12–256 characters.

When remote management is disabled, account, settings and connections pages/API routes reject external clients; calls and audit remain available. The policy also covers the bearer console API. Direct loopback/RFC1918/IPv6 unique-local clients are local. Forwarded headers from untrusted peers fail closed. Only explicitly configured exact trusted proxy addresses may supply `X-Forwarded-For`, which must contain one valid original client IP; the proxy must overwrite the header, not append a chain. A trusted proxy without that header is rejected. Never configure a proxy range or enable blanket framework proxy trust.

The shared `openConsoleAccount` service supports authenticated `update` calls and trusted offline `recover` operations. Recovery accepts optional `username`, `new_password`, and `allow_remote_management`; it uses the same validation and persistence, bypassing the old password only after the operator stops the running service and obtains its exclusive process lock. Keep password input and the initial credentials file out of command history, process arguments, logs, and public artifacts.

Verification covers one-time bootstrap, legacy password import, file permissions, compare-and-swap conflicts, offline recovery, browser CSRF, session revocation, remote restriction, and forged/ambiguous proxy headers. No real account or paid service is involved.
